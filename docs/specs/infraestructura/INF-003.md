# INF-003 — App despierta con un monitor externo y datos congelados

**Trello:** no tiene tarjeta propia. Decisión del equipo (Cilento, 26/11/2026), antes de pasarle la app a testers externos y de las 2 presentaciones que quedan.

## Historia de usuario
COMO persona que prueba StatsLine QUIERO que la app responda enseguida cuando entro PARA no pensar que está rota mientras arranca.

## Contexto
- **Render gratis se duerme.** Después de 15 minutos sin tráfico, el servicio se apaga, y la primera visita tarda alrededor de un minuto en responder (el 26/11/2026 se midieron 35 s).
- **Aiven gratis apaga la base por inactividad.** Pasó alrededor del 15/11/2026 y la app quedó caída hasta que se prendió a mano. El Developer tier (USD 5 por mes) no se apaga, pero el equipo decidió no pagarlo.
- **Los datos no hacen falta renovarlos:** el plan Pro de API-Football vence el 28/11/2026 y la prueba de Sportmonks el 30/11/2026. Las estadísticas se usan para 2 presentaciones y cambian poco, así que se congelan con la última sincronización.

## Decisión
1. **Monitor de UptimeRobot (plan gratis)** contra `https://statsline.onrender.com/api/v1/salud` cada **5 minutos**.
   - El health check consulta la base (`SELECT 1`), así que también le da actividad a Aiven.
   - Primero se pensó en 20 minutos, pero el plan gratis de UptimeRobot solo ofrece 5 o 30. Con 5, Render no llega a dormirse (se duerme a los 15) y sigue sin costo: el plan gratis de Render alcanza para un servicio prendido todo el mes (decisión del equipo, 27/11/2026).
   - El monitor lo crea y lo administra Cilento desde su cuenta. No hay código en el repo.
2. **Sincronización a mano.** `.github/workflows/sincronizacion.yml` deja de correr todos los días (se saca el `schedule`) y queda solo `workflow_dispatch`. Si vencieron las claves, una corrida manual falla sin tocar los datos (RN-025).

## Criterios de aceptación

```gherkin
Escenario: la app no se duerme por horas
  Dado el monitor de UptimeRobot activo cada 5 minutos
  Cuando entro a la app en cualquier momento
  Entonces responde enseguida, sin arranque en frío

Escenario: aviso si se cae
  Dado que Aiven apagó la base o Render no levanta
  Cuando el monitor recibe un error de /api/v1/salud
  Entonces le llega un mail a Cilento

Escenario: la sincronización no corre sola
  Dado el workflow "Sincronización diaria"
  Entonces no tiene schedule y solo se corre a mano desde Actions
```

## Fuera de alcance
- Pagar Render, Aiven, API-Football o Sportmonks.
- Un keep-alive con el cron de GitHub Actions: GitHub atrasa los crons hasta horas (el del 26/11/2026 corrió 10 h tarde).

## Dependencias
INF-001 y DAT-003. La última re-sincronización de Sportmonks (contadores en 0, RN-031) se corre antes de mergear este cambio.
