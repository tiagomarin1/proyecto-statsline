# INF-001 — Repo, stack, entorno y deploy

**Trello:** "Definir repo, stack y entorno de desarrollo" (Cilento + Marin, vence el 27/10).

## Historia de usuario
Como equipo de desarrollo, quiero un repositorio con backend, frontend, base de datos y deploy configurados, para que los 6 integrantes puedan programar features en paralelo desde el primer día.

## Contexto
La retrospectiva del Sprint 1 marcó "nueve entregables cerrados y cero código". Esta tarjeta es prerrequisito de todo el sprint.

## Criterios de aceptación

```gherkin
Escenario: levantar el entorno local desde cero
  Dado un clon limpio del repo y Docker instalado
  Cuando sigo los pasos de docs/SETUP.md
  Entonces tengo MySQL corriendo, las migraciones aplicadas, el seed de ligas y del usuario demo cargado
  Y GET /api/v1/salud responde 200 {"estado": "ok", "base_de_datos": "ok"}
  Y el frontend en http://localhost:5173 muestra la home

Escenario: correr los tests
  Dado el entorno local levantado
  Cuando corro `pytest` en backend y `npm test` en frontend
  Entonces ambos terminan en verde (al menos un test de humo en cada uno)

Escenario: deploy en Railway
  Dado un push a la rama main
  Cuando Railway construye la imagen
  Entonces la app queda publicada con el build de React servido por FastAPI
  Y /api/v1/salud responde 200 en la URL pública

Escenario: secretos fuera del repo
  Dado el repo
  Cuando busco claves o contraseñas
  Entonces solo hay .env.example con valores de ejemplo y .env está en .gitignore
```

## Entregables
- Estructura de carpetas de `ARQUITECTURA.md`.
- `backend/pyproject.toml` con fastapi, uvicorn, sqlalchemy, alembic, pymysql, pydantic-settings, pwdlib[argon2], pyjwt, httpx, pytest y ruff.
- `frontend` creado con Vite (react-ts), react-router, vitest y @testing-library/react.
- `docker-compose.yml` con MySQL 8 para desarrollo (`statsline_dev`) y para tests (`statsline_test`).
- Alembic configurado. La primera migración crea **todas** las tablas del modelo canónico.
- Semillas:
  - `semillas/ligas.py`: las 6 ligas con su `orden`. Los IDs de API-Football se confirman con `/leagues?country=Argentina`.
  - `semillas/usuario_demo.py`: Javier Ledesma, `javier@deportivonorte.com`, rol `director_tecnico`, club Deportivo Norte. La contraseña se toma de `DEMO_CONTRASENA`.
- `Dockerfile` multi-stage: build de Node → imagen Python que sirve `frontend/dist`.
- Railway: servicio web + MySQL + cron de sincronización (ADR-0006).
- GitHub: los 6 integrantes con acceso, una rama por feature (`feature/<ID>-descripcion`) y un PR hacia `main`.
- Los estilos base portados de `prototipo/styles.css` a `frontend/src/estilos/`.
