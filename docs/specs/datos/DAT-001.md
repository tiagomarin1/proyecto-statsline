# DAT-001 — Sincronizar jugadores desde API-Football

**Trello:** "Sincronizar datos de jugadores desde API-Football" (Cilento + Marin, vence el 29/10).

## Historia de usuario
COMO equipo de desarrollo QUIERO integrar y actualizar periódicamente los datos desde API-Football PARA que las fichas de jugadores muestren estadísticas vigentes.

## Contexto
La demo del 9/11 tiene que correr con datos reales (tarjeta "Preparar el Demo Day"). Ver ADR-0008.

## Criterios de aceptación

```gherkin
Escenario: sincronización exitosa de una liga
  Dado la liga Primera Nacional en la tabla liga y API-Football respondiendo (fixture)
  Cuando corro `python -m app.sincronizacion.api_football --liga <id>`
  Entonces se recorren todas las páginas de /players para la temporada actual
  Y se insertan o actualizan jugador, equipo y estadistica_temporada (upsert)
  Y las entradas de statistics[] de otras ligas se ignoran
  Y se registra una fila en sincronizacion con estado "ok", pedidos_usados y registros_actualizados
  Y se recalcula liga.cobertura (RN-020)

Escenario: métricas que la liga no publica
  Dado una página de Primera C donde passes y duels vienen null
  Cuando se sincroniza
  Entonces pases_precision_pct, duelos_totales y duelos_ganados quedan en NULL (nunca 0)

Escenario: la API falla a mitad de camino (Trello, criterio 2)
  Dado que la liga ya tiene datos de una sincronización anterior
  Y la página 3 responde error 500 tres veces seguidas
  Cuando corre la sincronización
  Entonces se hace rollback de esa liga y los datos anteriores quedan intactos
  Y sincronizacion.estado = "error" con el mensaje (sin la API key)

Escenario: cupo agotado
  Dado que la respuesta trae errors no vacío por límite de pedidos
  Cuando corre la sincronización
  Entonces se trata como error, igual que el escenario anterior

Escenario: todas las ligas
  Cuando corro el comando sin --liga
  Entonces se sincronizan las 6 ligas, una transacción por liga
  Y si una falla las demás igual se procesan
```

## Contrato
CLI, sin endpoint HTTP. Flags: `--liga <id_interno>` (opcional) y `--temporada <anio>` (opcional; por defecto la actual según `/leagues?current=true`). Código de salida 0 si todas las ligas quedaron "ok" y 1 si alguna falló.

## Entidades
Liga, Equipo, Jugador, EstadisticaTemporada, Sincronizacion.

## Reglas de negocio aplicables
RN-019 (posiciones), RN-020 (cobertura), RN-025 (sin pérdida de datos), RN-017 (se guardan **todas** las filas; la elección de una se hace al leer).

## Casos borde
- `games.rating` viene como string → se convierte a decimal. Si no se puede convertir, queda `NULL`.
- Jugador sin `birth.date` → `fecha_nacimiento` `NULL`.
- `games.position` desconocida → `posicion` `NULL`.
- Confirmar el formato de `passes.accuracy` (ver `INTEGRACIONES_EXTERNAS.md`) y ajustar el mapeo.

## Fuera de alcance
- El valor de mercado (es DAT-002).
- Fotos y escudos.
- Ligas fuera de las 6 del MVP.

## Dependencias
INF-001.
